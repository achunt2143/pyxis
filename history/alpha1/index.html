ALPHA 1

The first time Pyxis ran from power-on to a working app. One app, one window, and every layer of the system underneath it real.

What it did

Boot to an app

Alpha 1 proved the architecture end to end: kernel, services, compositor, message bus, web engine and app, all Pyxis's own.

A real terminal

The one app that worked end to end. What you type runs on the system and the output comes back over the bus, through the same bridge every later app would use.

  • It runs inside Vela, Pyxis's own build of the Gecko engine, at the address pyxis://terminal.
  • The window around it, with its title and three buttons, is drawn by Evo, Pyxis's compositor.
  • Restore it down and there is nothing behind it but Evo's plain background: no desktop yet.

Nothing behind it

Alpha 1 boots straight into the Terminal. The desktop shell existed, but did not start at boot yet.

  • Evo composites windows on the real kernel and draws their frames itself.
  • Echo, the message bus, carries calls and signals between every process.

The shell, waiting in the wings

Bloom, the desktop shell, ships in the image. Started by hand, it shows the shape the desktop would take: a top bar, a launcher rail, a dock. But its windows are drawn inside the shell's own page, and their contents are pretend.

  • The battery reads 50% and the Wi-Fi reads off, on a machine with no battery and a working network.
  • Files shows placeholder folders, not what is on disk.
  • Quick settings offers Dark Mode, Notifications and Auto-brightness.

Seven apps, by name

The app list names Browser, Contacts, File Manager, Notes, Settings, Terminal and Tasks. Only the Terminal does real work.

  • Vela gives every app its own pyxis:// origin, a real secure context of its own.
  • A bridge compiled into Vela gives apps the window.geckoOS API for files, apps, power and events.
Not yet

What it couldn't do

Written down at release, so the next alpha knew where to start.

  • Every app except the Terminal used made-up data.
  • The desktop shell didn't start at boot.
  • Any program on the bus could call any service: there was no permission model.
  • There was no way to install an app. Nova, the app host, was still a design.
  • Windows couldn't be minimized.
  • The engine still called itself Nightly and showed Firefox's security notice.
What came next

Alpha 2: a desktop

  • The shell started at boot, and apps opened as real windows of their own.
  • Nova and the installer service arrived, and Vroom became the Pyxis app toolkit.
