Pyxis alpha 1

Released 7 July 2026.

Alpha 1 is the first time Pyxis ran from power-on to a working app. The machine boots its own kernel, starts the Pyxis services, brings up the Evo compositor, and opens one real app: the Terminal, running inside Pyxis's own build of the Gecko web engine and talking to the system over the Echo message bus. It is not yet a usable desktop. It is the proof that the whole architecture holds together end to end.

Highlights

  • It boots. The image starts on a virtual machine, brings up every Pyxis service, and lands in a working app with no help.
  • One real app. The Terminal is live end to end. What you type runs on the system, and the output comes back through the bus.
  • Pyxis's own compositor. Evo draws every window, including its title bar and the minimize, maximize and close buttons.
  • Pyxis's own web engine. Vela, a from-source build of Gecko, opens apps from pyxis:// addresses in a chromeless window, each app at its own secure origin.
  • One message bus. Services, apps and the compositor all talk over Echo. Signals now reach other programs, not only the process that sent them.

What you see

  • The machine boots straight into the Terminal, filling the screen. Restore it down and Evo's plain background is behind it.
  • The desktop shell, Bloom, ships in the image but does not start at boot yet. Started by hand, it shows a top bar, a launcher rail on the left, a dock, an app list and a quick settings menu.
  • Bloom's windows are drawn inside the shell page itself, and everything in them except the Terminal is simulated: the files, the battery level and the network state are placeholders.
  • The app list names Browser, Contacts, File Manager, Notes, Settings, Terminal and Tasks. Only the Terminal does real work.

Under the hood

  • Evo, the Wayland compositor, composites windows on the real kernel and draws window frames itself.
  • Echo, the message bus, routes calls between services and now broadcasts signals to every connected program.
  • Synergy, the bridge between web pages and the system, gives apps a window.geckoOS API for files, apps, power and events.
  • Vela carries three Pyxis additions compiled into Gecko: the pyxis:// address scheme, the built-in bridge, and a kiosk mode that opens one window per app.
  • Rockhopper and Shift start at boot, register on the bus and supervise the other services.
  • The retired gaia shell and gonk prototype were removed.

Known issues

  • Only the Terminal works. Every other app surface uses made-up data.
  • Any program connected to the bus can call any service. There is no permission model yet.
  • There is no way to install apps. Nova, the app host, is still a design.
  • Windows cannot be minimized, and Evo does not read the display's scale.
  • Shift tries to register on the bus before the bus is ready and logs a warning at boot.
  • The browser engine still calls itself Nightly and shows Firefox's security notice.

Trying it

Pyxis alpha 1 boots as a disk image in QEMU. The reference VM has 2 GB of memory and 4 CPUs.
