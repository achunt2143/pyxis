Pyxis alpha 4

Released 25 September 2026.

Alpha 3 made Pyxis stop lying. Alpha 4 makes it useful. Its goal was "all my apps working": an app built with the Pyxis SDK, by someone who isn't Pyxis, installs through the App Installer, appears on the desktop with no change to Pyxis, opens in its own window, and uninstalls cleanly. Along the way, the window bugs that had followed Pyxis since alpha 2 were closed, and testing became real.

Highlights

  • Install an app and it shows up. A package built with pyxis-sdk installs through the App Installer and appears in the launcher, drawer, search and dock straight away. Remove it and it disappears.
  • No more fixed app list. The desktop reads Nova's live registry of apps, so the eight built-in apps and anything you install are all on equal footing.
  • Apps stay apps. An app opened a second time no longer comes back as a regular Firefox window with a toolbar.
  • Maximize, then restore. Restoring a maximized window no longer closes the app.
  • Restore from the dock. Click a minimized app's dock icon and it comes back.
  • Windows close properly. The close button asks the app to close, and a closed window is really gone.

What changed since alpha 3

  • An app with no built-in entry still appears, drawn with its own icon from its package, or a plain glyph when it has none.
  • The app drawer tells you whether it is still loading, can't reach the registry, or simply has no matches.
  • Minimizing an app marks it as in the background, and focusing it from the dock brings it back.
  • Firefox's sandbox notice no longer stacks a new bar in every app window.
  • The reference virtual machine now has 4 GB of memory: the eight built-in apps and the shell don't all fit in 2 GB.

Under the hood

  • Each install runs opkg install and then refreshes Nova's registry. Nova refuses to uninstall a packaged app itself and points to opkg remove, because opkg owns the files.
  • Evo removes destroyed windows (before, the count climbed with every launch), its close request is real, and maximize and unmaximize can be asked for over the bus.
  • Evo's window actions refuse a missing or malformed window id instead of answering success, and its error replies carry the real reason.
  • The cause of apps turning back into Firefox windows was Firefox's session restore rewriting the window's chrome two seconds after it opened. App windows are now exempt.
  • Shift was sending signals to process ids that weren't real kernel processes. It now refuses to signal anything it didn't start.
  • The bridge between apps and the system refuses a call that needs a capability the app's manifest didn't declare.

How it was checked

A new test harness boots the image headless and drives it over the serial console, and its assertions fail the run when something is wrong. Four suites passed on the release image: the package-to-uninstall flow, all eight apps launching and round-tripping through minimize and focus, the system service, and the regression guard for apps turning into Firefox windows. Bloom gained its first automated tests, which check the shell's picture of Nova against Nova's own source.

Known issues

  • Windows can't be resized by dragging their edges or corners yet.
  • Shift's process layer is still simulated underneath real bookkeeping.
  • The kernel lacks user namespaces, so the web engine's content sandbox is weaker than intended.
  • There is no install-time permission prompt, and no way to see or revoke what an app was granted.
  • There is no sound.
  • A minimized app keeps all of its memory.

Trying it

Pyxis alpha 4 boots as a disk image in QEMU. Give the VM 4 GB of memory.
