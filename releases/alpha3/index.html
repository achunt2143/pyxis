Pyxis alpha 3

Released 20 September 2026.

Alpha 3's rule was "nothing lies to the user." Alpha 2 looked finished in places where it wasn't: the battery read 50% on a machine with no battery, the network read disconnected on a working connection, Files showed folders that weren't there, and the App Installer had no package manager to call. Alpha 3 makes each of those either real or honest about what it can't do, and makes the boot itself reliable.

Highlights

  • Honest status. The top bar's clock ticks. The network indicator reads the kernel, so a wired connection shows as connected. A machine with no battery says so instead of showing a made-up number.
  • Quick settings that work. Switches that did nothing were removed. Dark Mode and "Show percentage in top bar" really change things now.
  • Files shows your files. Folders list what is really on disk, one unreadable entry no longer blanks the whole folder, and images preview inline.
  • A real package manager. opkg ships in the image for the first time, so the App Installer has something to install with.
  • The App Installer on the desktop. It is in the app list, with a four-step flow: choose a package, review it, install, done.
  • Desktop search. Type in the top bar and matching apps appear. Press Enter to open one.
  • Power works. Shut down powers the machine off and Restart restarts it.
  • The services survive boot. A bug killed the background services moments after startup. Each now runs in its own session, so an unattended boot brings up everything.

What changed since alpha 2

  • The top bar shows real Wi-Fi or wired status and the time, ticking on the minute.
  • Quick settings lists Notifications, Dark Mode, the network's status and its interface name, and the battery.
  • Terminal, Files, Notes, Contacts, Tasks, Settings, Browser and App Installer were each built out further on the remochi component library.
  • Evo draws app title bars with the triangle, square and circle controls that later became the Pyxis window controls.

Under the hood

  • The boot script starts each daemon in its own session, with no terminal. Before, they shared the boot script's process group and died when it finished. This also explained several alpha 2 reports that looked like bus bugs.
  • opkg 0.10.0 is built from a pinned, checksum-verified source tarball during the image build, because Debian packages no opkg at all.
  • The network service reads /proc/net/route and /sys/class/net directly instead of calling a tool that wasn't in the image.
  • Reading files gained a binary-safe mode with a size cap, which is what lets Files preview images.
  • Evo now binds an app's window to its session through the daemon. Apps launch in their own process group, so a browser that restarts itself isn't orphaned.
  • On-device checks became a repeatable process: the image boots in QEMU and a script drives it over the serial console.

Known issues

  • The launcher, dock and search still use a fixed list of apps. An app installed from a package doesn't appear on the desktop yet.
  • Clicking a minimized app's dock icon does not bring it back.
  • Restoring a maximized window down closes the app.
  • Windows can't be resized.
  • An app can open as a regular Firefox window, toolbar and all, instead of a clean app window.
  • Sleep isn't supported in the VM and says so.
  • There is no sound.
  • Shift reports made-up process information over the bus.

Trying it

Pyxis alpha 3 boots as a disk image in QEMU. The reference VM has 2 GB of memory and 4 CPUs.
